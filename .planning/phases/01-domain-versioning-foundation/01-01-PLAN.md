Créer le namespace `App\Entity\AssetTransformation` avec deux fichiers (un par classe — pattern projet : `api/src/Entity/Asset/Asset.php`, `AssetFlag.php`).

**AssetTransformation.php** :
- Propriétés `private` (per CLAUDE.md), getters/setters retournant `static`
- `#[ORM\Entity]`, `#[ORM\Table(name: 'asset_transformation')]`
- `#[UniqueEntity(fields: ['code'], message: 'Une transformation avec ce code existe déjà.')]`
- `#[ApiFilter(SearchFilter::class, properties: ['code' => 'ipartial', 'label' => 'ipartial'])]`
- `#[ApiResource(operations: [new GetCollection(), new Get(), new Post(security: "is_granted('ROLE_ADMIN')"), new Patch(security: "is_granted('ROLE_ADMIN')"), new Delete(security: "is_granted('ROLE_ADMIN')")], normalizationContext: ['groups' => ['asset_transformation:read'], 'enable_max_depth' => true], denormalizationContext: ['groups' => ['asset_transformation:write']])]`
- `#[MenuGroup('Settings')]`
- Propriétés :
  - `$id: ?int` — ORM Id/GeneratedValue, group `asset_transformation:read`
  - `$code: ?string` — `#[ORM\Column(length: 50, unique: true)]`, `#[Assert\NotBlank]`, groups `read+write`. **Ne PAS ajouter `#[AppAssert\TransformationCode]` ici — c'est le rôle du Plan 03.**
  - `$label: ?string` — `#[ORM\Column(length: 150)]`, `#[Assert\NotBlank]`, groups `read+write`
  - `$versionHash: ?string` — `#[ORM\Column(length: 40, nullable: true)]`, group `asset_transformation:read` **uniquement** (jamais writable — Pitfall D du RESEARCH). Setter `setVersionHash(?string)` package-private en pratique (PHP n'a pas package-private, donc public — le listener est le seul appelant légitime ; documenter en docblock `@internal Set automatically by TransformationHashListener — do not call from controllers.`)
  - `$steps: Collection<int, TransformationStep>` — OneToMany, `mappedBy: 'transformation'`, `cascade: ['persist', 'remove']`, `orphanRemoval: true`, `#[ORM\OrderBy(['position' => 'ASC'])]`, `#[MaxDepth(1)]`, groups `read+write`
- Constructeur initialise `$this->steps = new ArrayCollection()`
- Méthodes collection : `addStep(TransformationStep $step): static` (qui set la relation inverse `$step->setTransformation($this)`), `removeStep(TransformationStep $step): static` (qui nullifie la relation inverse si la step pointe encore vers `$this`). Voir pattern Symfony/Doctrine standard.

**TransformationStep.php** :
- `#[ORM\Entity]`, `#[ORM\Table(name: 'transformation_step')]`
- `#[ApiResource(operations: [])]` — Pitfall F du RESEARCH : pas d'opérations CRUD directes (sinon un PATCH sur un step seul ne déclencherait pas le recompute du hash parent en Plan 04)
- `#[MenuGroup('hidden')]`
- Propriétés :
  - `$id: ?int`
  - `$transformation: ?AssetTransformation` — ManyToOne, `inversedBy: 'steps'`, `#[ORM\JoinColumn(nullable: false, onDelete: 'CASCADE')]`, `#[MaxDepth(1)]` (pas de group `read` pour éviter la récursion JSON-LD)
  - `$type: ?StepType` — `#[ORM\Column(length: 30, enumType: StepType::class)]`, `#[Assert\NotNull]`, groups `asset_transformation:read+write`
  - `$params: array = []` — `#[ORM\Column(type: Types::JSON, nullable: true)]`, `#[Assert\Type('array')]`, groups `asset_transformation:read+write`. Phase 1 = pas de validation profonde (HANDLERS-03 = Phase 3).
  - `$position: int = 0` — `#[ORM\Column(options: ['default' => 0])]`, `#[Assert\PositiveOrZero]`, groups `asset_transformation:read+write`
- Constructeur vide. Getters/setters retournent `static`.

**Tous les imports nécessaires en haut de chaque fichier** : `Doctrine\ORM\Mapping as ORM`, `Doctrine\DBAL\Types\Types`, `Doctrine\Common\Collections\{ArrayCollection, Collection}`, `Symfony\Component\Serializer\Attribute\Groups`, `Symfony\Component\Serializer\Attribute\MaxDepth`, `Symfony\Component\Validator\Constraints as Assert`, `Symfony\Bridge\Doctrine\Validator\Constraints\UniqueEntity`, `ApiPlatform\Metadata\{ApiResource, ApiFilter, GetCollection, Get, Post, Patch, Delete}`, `ApiPlatform\Doctrine\Orm\Filter\SearchFilter`, `App\Attribute\MenuGroup`, `App\Enum\StepType`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (admin PWA / curl) → API JWT | Tout payload POST/PATCH est non-confiant ; passe par denormalization + validators |
| API → DB | Doctrine bound params ; pas de SQL string concat |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | Spoofing | POST /api/asset_transformations | mitigate | `security: "is_granted('ROLE_ADMIN')"` sur Post/Patch/Delete ; GET/GetCollection ouverts à ROLE_USER (lecture seule) — pattern AssetFlag |
| T-01-01-02 | Tampering | versionHash via API | mitigate | versionHash absent du group `:write` (Pitfall D RESEARCH) — l'API ne peut pas écraser. Setter PHP documenté `@internal` |
| T-01-01-03 | Tampering | TransformationStep CRUD direct | mitigate | `#[ApiResource(operations: [])]` — pas d'endpoint /api/transformation_steps. Tout passe par cascade depuis le parent (Pitfall F RESEARCH) |
| T-01-01-04 | Information disclosure | MaxDepth récursion JSON-LD | mitigate | `#[MaxDepth(1)]` sur la relation + `enable_max_depth: true` dans normalizationContext — empêche le serializer de chaîner step→transformation→steps→… |
| T-01-01-05 | Elevation of privilege | Mass-assignment de `versionHash` ou champs non groupés | mitigate | Serializer groups stricts : `:write` ne contient PAS versionHash ni id. Tout champ hors groupe est ignoré par denormalize |
| T-01-01-06 | DoS | params JSON arbitrairement gros | accept | Phase 1 : `Assert\Type('array')` uniquement. La validation profonde + size cap arrivent en HANDLERS-03 (Phase 3). Risque faible en Phase 1 (admin authentifié) |
| T-01-01-07 | Injection (SQLi) | code/label/params persistés | mitigate | Doctrine ORM bound params via PDO ; column types stricts (VARCHAR length-bound, JSON type-checked par Postgres) |
| T-01-01-08 | SSRF | Phase 1 ne déclenche aucun appel sortant | accept | Aucune surface SSRF en Phase 1 (pas d'asset fetch, pas d'URL params). Documenté pour traçabilité — surface réelle en Phase 2/4/5 |
</threat_model>
