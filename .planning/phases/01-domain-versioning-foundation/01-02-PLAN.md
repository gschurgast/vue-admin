```php
<?php
namespace App\Service\AssetTransformation;

use App\Entity\AssetTransformation\AssetTransformation;
use App\Entity\AssetTransformation\TransformationStep;

final class TransformationHasher
{
    /**
     * Compute a deterministic sha1 hash over the ordered step list.
     *
     * Canonicalisation rules (v1 — NEVER change without coordinated cache invalidation):
     * 1. Steps ordered by position ASC (re-sorted defensively even if ORM already orders).
     * 2. Each step → ['type' => $step->getType()->value, 'params' => canonicalizeParams(...)].
     * 3. canonicalizeParams: recursively drop null values, ksort keys.
     * 4. json_encode with JSON_UNESCAPED_UNICODE | JSON_PRESERVE_ZERO_FRACTION | JSON_THROW_ON_ERROR.
     * 5. sha1(<utf8 string>) → 40-char hex.
     *
     * NO algorithm-version prefix in v1.0. If canonicalisation rules change in v2, prepend "v2:" before sha1.
     */
    public function compute(AssetTransformation $transformation): string
    {
        $steps = $transformation->getSteps()->toArray();
        usort($steps, static fn(TransformationStep $a, TransformationStep $b) => $a->getPosition() <=> $b->getPosition());

        $canonical = array_map(
            fn(TransformationStep $s) => [
                'type'   => $s->getType()->value,
                'params' => $this->canonicalizeParams($s->getParams() ?? []),
            ],
            $steps,
        );

        return sha1(json_encode(
            $canonical,
            JSON_UNESCAPED_UNICODE | JSON_PRESERVE_ZERO_FRACTION | JSON_THROW_ON_ERROR,
        ));
    }

    private function canonicalizeParams(array $params): array
    {
        $filtered = [];
        foreach ($params as $key => $value) {
            if ($value === null) continue;
            $filtered[$key] = is_array($value) ? $this->canonicalizeParams($value) : $value;
        }
        ksort($filtered);
        return $filtered;
    }
}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Tampering | Hash drift entre versions du hasher | mitigate | Golden-hash test figé : tout changement de canonicalisation déclenche RED en CI. Documenté en haut du fichier "NEVER change without coordinated cache invalidation" |
| T-01-02-02 | Repudiation | Calcul non déterministe | mitigate | json_encode déterministe avec PRESERVE_ZERO_FRACTION + UNESCAPED_UNICODE ; ksort recursive ; usort sur position. Tests testDeterministicAcrossRuns + testParamKeyOrderIndependent |
| T-01-02-03 | Info disclosure | sha1 comme primitive cryptographique | accept | sha1 utilisé comme **fingerprint déterministe**, pas comme hash de sécurité (cf. RESEARCH §Security Domain V6). Collision adverse non pertinente — l'attaquant ne contrôle pas l'espace des steps (admin only) |
| T-01-02-04 | DoS | json_encode sur params très imbriqués | accept | canonicalizeParams est récursif. Limite implicite par la profondeur d'imbrication des params JSON (Postgres tolère jusqu'à 100s de niveaux). Risque négligeable — params sont admin-only et validés en Phase 3 |
