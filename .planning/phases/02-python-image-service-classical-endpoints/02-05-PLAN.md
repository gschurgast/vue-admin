    3. Create `embedder/README.md` documenting the endpoint contracts for Phase 3:
       ```markdown
       # embedder/ — Asset Image Service

       FastAPI service exposing:
       - `POST /embed` — CLIP ViT-B/32 embedding (Phase 0, unchanged)
       - `POST /img/{resize,crop,rotate,format-convert,add-background}` — Pillow ops (Phase 2)
       - `GET /health` — model loading status

       Runs on `embedder:8000` inside the docker network. Not exposed publicly.

       ## Shared invariants (all `/img/*` endpoints)

       1. Multipart `image` field is **required** and decoded via `core.image_utils.decode_image()`:
          - EXIF Orientation is auto-applied (`ImageOps.exif_transpose`)
          - Images > 50 MPx are rejected with 422 (DoS guard)
          - SVG is rejected with 422 (raster only)
          - Corrupt bytes return 422 (never 500)
       2. `params` field is a JSON string validated by Pydantic v2 → 422 on invalid.
       3. Response is the processed binary with the appropriate `Content-Type` and an `X-Processing-Time` header (ms).
       4. Output format = source format unless `/img/format-convert` is used.

       ## `POST /img/resize`

       ```json
       { "width": 800, "height": 600, "mode": "fit|cover|contain", "upscale": false }
       ```

       - `mode=fit` (default): preserve ratio, fit inside (w,h)
       - `mode=cover`: exact (w,h), center-crop overflow
       - `mode=contain`: exact (w,h), pad to fit
       - `upscale=false` (default): never enlarge beyond source
       - At least one of `width`/`height` is required.

       ## `POST /img/crop`

       Absolute mode:
       ```json
       { "x": 10, "y": 10, "width": 200, "height": 200 }
       ```
       Aspect-ratio mode:
       ```json
       { "aspectRatio": 1.777, "anchor": "center|top|bottom|left|right" }
       ```

       Out-of-bounds absolute crop returns 422.

       ## `POST /img/rotate`

       ```json
       { "angle": 45.0, "expand": true, "background": "#RRGGBB" }
       ```

       - For RGBA sources, rotation produces transparent corners (background ignored).
       - For RGB sources, corners filled with `background` (default `#000000`).
       - Invalid hex color → 422.

       ## `POST /img/format-convert`

       ```json
       { "format": "png|jpg|jpeg|webp|avif", "quality": 85 }
       ```

       - `jpg` is normalised to Content-Type `image/jpeg`.
       - AVIF via `pillow-avif-plugin` (registered at module load).
       - RGBA → JPEG: composite over white background, response includes `X-Alpha-Flattened: true`.
       - `quality` is ignored for PNG, applied to JPEG/WebP/AVIF.

       ## `POST /img/add-background`

       Two modes via `params.type`:

       **Color (single multipart field):**
       ```json
       { "type": "color", "color": "#RRGGBB" }
       ```

       **Asset (TWO multipart fields):**
       ```json
       { "type": "asset", "assetId": 42 }
       ```
       Plus a second multipart field `background_image` containing the bytes of the background asset.

       **SSRF-safe by construction:** the service has no S3/AWS credentials and never issues
       outbound HTTP. The PHP orchestrator (Phase 3) resolves the asset bytes via Flysystem
       and includes them inline. `assetId` is for log traceability only — never used for I/O.
       Any field named `url`, `src`, or `href` in params is rejected with 422 (anti-SSRF
       deep defense).

       ## `GET /health`

       ```json
       {
         "status": "ok",
         "models": {
           "clip":              { "status": "loaded|lazy", "name": "clip-ViT-B-32", "dim": 512 },
           "birefnet":          { "status": "not_loaded" },
           "stable_diffusion":  { "status": "not_loaded" }
         }
       }
       ```

       Phase 4 will set `birefnet.status` to `loaded`/`lazy` once the BiRefNet model is integrated.
       Phase 5 will set `stable_diffusion.status` once SD is integrated.

       ## Tests

       ```bash
       docker compose exec embedder pytest tests/ -v
       ```
